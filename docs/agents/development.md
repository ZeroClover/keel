# Development, CI and release

Verified against commit `9070252f` (2026-10-22).

## Toolchain

- Go `1.23` (`go.mod`, CI, and `golang:1.23.4-alpine` in `Dockerfile`). No `vendor/` directory; modules are downloaded.
- `CGO_ENABLED=0` everywhere; SQLite is `modernc.org/sqlite`.
- No Go linter is configured (no golangci config, no `go vet` in CI). Run `gofmt` on files you touch.
- UI: Node 16 and yarn (see `docs/agents/ui.md`).

## Makefile targets

| Target | Status |
|---|---|
| `test` | Canonical unit tests: `go test -json -v $(go list ./... \| egrep -v /tests) -cover \| tparse`; installs `tparse` first |
| `build` | `CGO_ENABLED=0 GOOS=linux` build to `cmd/keel/keel` |
| `run` | `go install ./cmd/keel` then `keel --no-incluster --ui-dir ui/dist` |
| `run-ui` | `cd ui && yarn run serve` |
| `lint-ui` | Broken: `yarn run lint` runs in the repo root |
| `install`, `install-debug`, `e2e`, `run-debug` | `install` cross-compiles with `GOOS=linux`, so on macOS it doesn't produce a runnable `keel` on `PATH`; the targets depending on it only work on Linux |
| `image`, `alpha`, `image-debian`, `build-ui` | Tag/push the upstream `keelhq/keel` image; images are built by CI instead |
| `build-binaries`, `build-arm`, `compress`, `fetch-certs`, `armhf*`, `aarch64*`, `arm` | Legacy; several reference files that don't exist |

## Tests

- **Unit tests** sit next to the code (`*_test.go`). Without network access, tests in `registry/` and `registry/docker/` that call Docker Hub, Quay and Zalando's registry fail; tests needing AWS, Artifactory, Docker Hub or GitLab credentials skip themselves. `provider/helm3/implementer_test.go` is always skipped.
- **E2E tests** (`tests/`, package `tests`, no build tags) run `keel --no-incluster --kubeconfig …` from `PATH` against a real cluster, create `keel-e2e-test-*` namespaces and pull from public registries. Run with `cd tests && go test` on Linux after installing the binary. If no kubeconfig exists, `TestMain` prints a warning and exits 0, so a "pass" may mean nothing ran.
- `scripts/start-local-cluster.sh` creates a kind cluster `keel-dev` (installs kind/kubectl if missing, uses sudo).

## CI (`.github/workflows/ci.yml`, the only workflow)

Runs on pushes to `master`, every tag push, PRs to `master`, and manual dispatch.

| Job | What it does |
|---|---|
| `test` | `make test` on Go 1.23 |
| `lint-ui` | `yarn` + `yarn run lint --no-fix` in `ui/` on Node 16 |
| `docker` | After both: `docker/github-builder` reusable workflow builds `linux/amd64` and `linux/arm64` on native runners (no QEMU) and pushes to `ghcr.io/<repo>` except on PRs. Tags: branch, git tag, semver, and `latest` for any tag |
| `verify-docker-manifest` | Non-PR: checks every pushed tag has both architectures |
| `chart-release` | Only for tags starting with `v`: writes the version (without `v`) into `chart/keel/Chart.yaml` `version`/`appVersion` and runs `helm/chart-releaser-action` |

Requirements: `openspec/specs/docker-image-workflow/spec.md`; the cgo-free build rules are in `openspec/specs/cgo-free-builds/spec.md`.

## Release

Push a tag `vX.Y.Z` on `master`. One CI run builds and pushes the multi-arch image, verifies the manifests, then publishes the chart: chart-releaser creates a GitHub release `keel-X.Y.Z` with the packaged chart and updates `index.yaml` on the `gh-pages` branch (served at `https://zeroclover.github.io/keel/`). Don't bump `chart/keel/Chart.yaml` by hand; its `0.0.1` values are placeholders. Tags without the `v` prefix still push images (including `latest`) but publish no chart.

## Production image (`Dockerfile`)

Go build stage (`CGO_ENABLED=0`, target-arch aware) → UI stage on the build platform (`yarn`, `yarn run lint --no-fix`, `yarn run build`) → `alpine:3.20.3` runtime with the binary at `/bin/keel`, UI at `/www`, user `keel` (uid 666), `VOLUME /data`, `XDG_DATA_HOME=/data`, port 9300.

## OpenSpec workflow

- `openspec/specs/<capability>/spec.md` are the current requirements: cgo-free-builds, docker-image-workflow, helm-chart-config, image-policy, image-poll-watcher, image-update-pipeline, notifications, persistence, provider-update-decision, registry-client, web-dashboard.
- `openspec/config.yaml` `context` points OpenSpec's artifact instructions at `AGENTS.md` and this directory; keep it a pointer rather than copying rules into it.
- A change lives in `openspec/changes/<name>/` (`proposal.md`, `design.md`, `tasks.md`, delta specs under `specs/`). Archiving moves it to `openspec/changes/archive/<date>-<name>/` and merges the deltas into `openspec/specs/`.
- Commands: `/opsx:explore`, `/opsx:propose`, `/opsx:apply`, `/opsx:update`, `/opsx:sync`, `/opsx:archive` in Claude Code; `$openspec-*` skills in Codex. The skill and command files under `.claude/` and `.agents/` are generated by `openspec update`; edit them only through OpenSpec.
- Change documents in this repo are often written in Chinese; specs and code comments are English.
